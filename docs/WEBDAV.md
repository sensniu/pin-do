# WebDAV 同步说明

1. 在“PinDo → 设置… → 同步”填写 HTTPS 服务器地址、账号、应用授权密码，以及**手动填写的专用同步目录**。目录没有默认值，不能留空。例如服务器地址为 `https://dav.jianguoyun.com/dav/`、目录为 `PinDo`；多台设备使用相同目录。首次连接会在服务器地址下逐级创建所配置的缺失文件夹，服务器地址本身应为有效的 WebDAV 入口。
2. 点击“连接并合并”。软件用固定探测槽位分别验证 ETag 更新、过期写入拒绝、安全创建和临时文件删除，再选择条件 PUT 或经过验证的“不覆盖目标”MOVE 创建方式，并为本地数据建立同步状态。服务器的 ETag 按原值使用，包含没有引号的格式；已有索引仍须通过 If-Match 更新。缺少安全能力时保留本地内容并拒绝开启同步。应用密码保存在 macOS 钥匙串，不进入数据库、备份或同步文件。
3. 连接后默认自动同步：本地更改先落盘，通常约 5 秒后合批发送，持续编辑时最长约 30 秒安排一轮；启动、回到前台及约每 2 分钟也尝试同步。断网不影响本地保存，重试遵守退避与服务端限流。
4. 白板工具栏的小刷新按钮用于立即同步，可见下拉可打开状态和冲突处理；“文件 → 同步状态…”也保留入口。暂停同步保留待发内容，暂停期间自动与手动同步都会停止；点击“恢复同步”使用原配置与钥匙串密码继续。
5. 同一字段的并发不同值保留为候选，可在“设置 → 同步”的待处理问题区域选择采用版本；不同字段的更改自动合并。采用版本后清理已解决的旧正文。完成与放弃冲突暂不计入任一结果，待明确处理。
6. 专用云目录完整清空后，新版自动创建新库并重新上传本地项目、事项、完成/放弃记录及尚未解决的候选。原配置已启用时自动开始；尚未启用时点击“连接并合并”。既有v3库会原地升级能力标记，保留原库ID、记录和目录；全部设备需升级到v1.1.0及以上。更早的云协议仍不支持读取，也不会替用户清理旧云目录。

本地数据库仍由 SwiftData 管理，**不会上传 SQLite 数据库文件或 WAL 文件**。云端布局为：

```text
专用目录/
  library.json                    同步库身份与能力版本 v4
  index.json                      事项/项目 ID 与最新修订号
  records/
    todo-<UUID>.json               该事项的最新字段、必要业务记录与未解决候选
    project-<UUID>.json            该项目的最新字段与必要代次信息
  _work/                          可恢复工作区，正常空闲无工作文件
    <writerID>.<SHA256>.intent.json   内容不可变的完整恢复输入，确认后删除
    <writerID>.<SHA256>.payload.json  内容不可变的安全创建正文，确认后删除
    <writerID>.probe-{a,b,c}.json   不含业务内容的安全能力探测
```

库能力版本v4支持预计开始与截止组成的完整安排，以及完成时的安排快照；记录、索引和可恢复工作区继续沿用v3容器。升级以ETag条件更新library.json，旧版客户端看到v4后停止同步，避免丢弃新信息。同一安排的并发修改保留完整候选，不分别拼接起止时间。

每个事项/项目一个固定路径，内容更新使用 ETag/If-Match；首次创建延续已验证的条件 PUT 或不覆盖 MOVE。只下载索引中变化的记录，无修改刷新不上传业务内容。每轮最多下载/发布各 24 条记录，之后继续；不用逐条重放历史。单记录上限 8 MiB、索引上限 4 MiB，超限保留完整本地内容并停止相应发送，不截断备注。索引只有 ID/修订号，没有所有备注正文。

本地只保留当前字段/未解决候选、当前有效完成/放弃凭据、待发与在途修改、每条记录的最高确认进度。普通创建/编辑/撤回事件不累计；离线多次改同一字段合并为最后的待发值；在途请求封存后继续编辑，保留下一批最新内容。项目使用当前激活代次及每个写入身份的失效/因果前沿，反复归档恢复不保留整条生命周期链。事项终态、关键时间及必要项目来源属于业务数据，继续保存；无法确认的历史转出时间记为未知。

工作意图和上传正文使用包含内容 SHA-256 的路径，同一路径永不保存另一份不同内容。每次串行处理一项，重试相同字节复用原路径，不将临时文件当历史归档。记录发布前先保存完整意图；任何新版设备均可接续合并、修复索引，确认后删除该不可变路径。后续操作使用不同路径，旧清理不会删到新输入，因此兼容 DELETE 忽略 If-Match 的服务器；业务记录及索引更新仍严格使用条件写入。删除响应丢失可读回确认，没有证明的内容不会因时间过期被删除。正常同步完成后工作文件清空，允许空 `_work/` 目录。断网、权限不足或无法校验的唯一输入会保留并提示，恢复确认后才回收。

自动备份固定为 `Backups/recovery.latest.pindobackup`，先校验、原子替换，再回收应用旧轮换备份和已完成操作的安全副本；不维护每日/每版本历史文件。备份失败保留上一份有效副本，用户手动导出的文件不参与自动回收。本地受管文件使用固定 `.pending` 槽位，成功后消失，中断后重用或恢复。SQLite 的 WAL/SHM 和可复用空页属于数据库维护，不直接删除。

实际连接必须通过条件写入、安全创建及临时文件删除验证；本项目未访问真实坚果云账号联调。同步后的备份恢复使用合并方式，备份缺少的事项不会删除当前内容。已有绑定暂不支持直接更换服务器/账号/目录，但同一专用云目录完整清空后可自动重新初始化。发现已知索引条目丢失、版本回退、记录缺失、身份重复或损坏时停止并保留本地数据。当前采用记录级条件提交，多记录操作可能跨轮到达，依赖未齐时暂存等待；不宣称整个云库一次全局提交。


本地存储和备份说明见 [安装与数据说明](../INSTALL.md)。

v1.1.0导出的备份使用第2版校验封装，需要新版应用恢复；仍支持读取旧备份。它不增加轮换历史或额外云文件。
