# PinDo

Mac 原生便利贴白板待办软件。当前版本 **v0.10.1**：WebDAV 每个事项/项目只更新最新记录，不累计普通编辑流水或同步历史包；中断工作可恢复，确认后条件清理，本地只维护一份最新恢复备份。完成/放弃事项、必要归属和未解决冲突保留。包含菜单栏常驻、关闭窗口保留后台、退出防误触提示、默认关闭的开机自启，以及自由拖动与独立白板布局。

本轮提供本机使用的 Release 安装包，由用户自行安装。自动化使用临时数据库和模拟服务端，未操作正式数据。本轮只进行非 UI 验证，没有启动应用窗口或操作真实云目录。真实开机登录、坚果云账号与 Android 互操作仍需在各自环境验证，详细记录见规划第 30 节。

需求和后续规划维护在 [PROJECT_PLAN.md](PROJECT_PLAN.md)；安装、升级和数据说明见 [INSTALL.md](INSTALL.md)。

## 安装

安装包：`build/releases/PinDo-0.10.1-arm64.dmg`，适用于 Apple silicon、macOS 14 及以上。

1. 真正退出正在运行的旧版 PinDo。常驻版本需从退出菜单确认，或按两次/长按 `⌘Q`；红色按钮只关窗口。升级前可从“数据 → 导出备份…”另存一份备份。
2. 从 v0.10.0 升级本修正版无需再次清空云端，启动后重新连接同步即可。从 v0.9 及更早版本升级仍按原约定：先退出所有旧客户端，再手动清空专用 WebDAV 目录（含 `library.json`），保留本机 Application Support 数据目录。
3. 打开 DMG，将 `PinDo.app` 拖到镜像窗口里的“应用程序”文件夹图标。
4. 如提示已存在旧版，选择替换；无需手动复制或另找安装目录。
5. 推出镜像，从“应用程序”启动。软件先检查本地数据，按需要自动备份和升级，再显示白板。

新安装从空白白板开始；升级会保留旧事项、完成/放弃历史与草稿，将原类别转换为项目。内部 ID 和关联自动维护，不需要手动转换数据。替换程序不会删除 `~/Library/Application Support/PinDo/`。

## 日常操作

- 菜单栏的单色“便利贴＋图钉＋勾选”图标随系统深浅色显示；点击菜单可打开白板、查看同步状态、手动同步、配置同步和退出。关闭白板后应用继续运行，再打开保留草稿及本次运行的布局。
- 第一次按 `⌘Q` 显示提示，2 秒内再按一次或按住约 1 秒才真正退出；短按松开取消本次长按，超时和切换应用取消确认。鼠标点退出菜单会显示确认。退出先保存本地草稿与备份，待发内容下次继续。
- 开机自启默认关闭。安装到“应用程序”后可从菜单栏按需开启；系统需要允许时显示等待状态。登录自启仅后台运行，不弹白板；普通手动启动打开白板。

- 点击 `+` 或 `⌘N` 新增，只填标题后按 `⌘↩` 即可保存。星数默认 1，DDL 和备注按需展开；修改后的取消和删除都有明确确认。
- 在具体项目白板新建时自动归属该项目；在全部或未分配白板中默认未分配。点击编辑器的项目标签可按需更改。
- 顶部左侧固定“全部待办”和“未分配项目”，右侧是横向滚动的彩色项目标签；项目名完整显示，选中项有勾选和描边。右侧栏已移除。
- 启动回到上次白板（失效项目回到全部），按当前紧急程度重新整理；本次运行内，每张白板独立保留位置和堆叠顺序，切换只刷新内容，不重排已有卡片。重新启动会覆盖手动位置。
- 拖便利贴可自由摆放、重叠，点击编辑或拖动会置顶；拖白板空白处平移。新增事项只寻找新卡片的合适空位，已有卡片不动；颜色按时间和 DDL 正常刷新。远端同步收到新增事项也遵循此规则。
- 白板右上角九宫格按钮及“白板 → 重新整理白板”仅整理当前白板，覆盖手动位置、解除堆叠并适配全局；旁边的圆形刷新箭头用于 WebDAV 同步。底部“适应”及 `⌘0` 只调整视野。
- 菜单“项目 → 项目管理…”支持新建、编辑名称和颜色、归档、恢复和删除。颜色编辑后按“保存”提交，取消保留原色。归档自动将未完成事项转入未分配；恢复不自动移回。同名项目通过独立 ID 区分。
- 删除项目时，选择将未完成事项转入未分配或放弃；已完成历史及原项目关联保留。
- 便利贴右上角勾选图标代表完成；全窗口只保留最近一次完成的 3 秒撤回控件，切换白板不重置倒计时。
- 点击便利贴展开编辑，可直接保存并完成；删除代表放弃并保留独立记录。缩小到 70% 以下时，完成图标也先展开，避免误触。双指缩放、滚动或拖动白板浏览，`⌘0` 适应白板。
- 便利贴宽度固定，高度按标题和备注自动调整；标题最多两行，备注最多三行，展开查看完整内容。文字变高或变短时保留卡片中心和邻居位置，允许重叠，当前缩放不变；可按 `⌘0` 查看完整范围。撤回完成恢复原位置，位置已被占用时也不挤动其他卡片。
- “PinDo → 外观设置…”（`⌘,`）可以选择渐变起点、终点和逾期固定色，支持颜色选择器、六位色值、预览与恢复默认。七天内逐渐接近终点色，超过七天使用起点色；逾期不再渐变。保存颜色不会重排卡片。
- 外观随 macOS 切换为中性浅色/石墨深色；无 DDL 为中性灰，默认临近 DDL 渐变紫，逾期为固定珊瑚色并排在外围。文字根据纸面自动选择黑色或白色，次要文字也保持清晰。仅全部待办的便利贴使用项目色边框，具体项目和未分配白板使用中性轮廓；编辑态同样遵循此规则。

项目和事项 ID 不需要用户配置。Debug 的“开发预览”菜单可临时切换深浅外观和窗口尺寸，不改变系统设置，也不包含在 Release 中。

当前没有完整的归档事项浏览、统计总览或自动下载更新；同步冲突窗口仅提供受影响的已结束事项内容查看。

## WebDAV 同步（当前源码）

1. 在“数据 → WebDAV 同步设置…”填写 HTTPS 服务器地址、账号、应用授权密码，以及**手动填写的专用同步目录**。目录没有默认值，不能留空。例如服务器地址为 `https://dav.jianguoyun.com/dav/`、目录为 `PinDo`；多台设备使用相同目录。首次连接会在服务器地址下逐级创建所配置的缺失文件夹，服务器地址本身应为有效的 WebDAV 入口。
2. 点击“连接并合并”。软件用固定探测槽位分别验证 ETag 更新、过期写入拒绝、安全创建和临时文件删除，再选择条件 PUT 或经过验证的“不覆盖目标”MOVE 创建方式，并为本地数据建立同步状态。服务器的 ETag 按原值使用，包含没有引号的格式；已有索引仍须通过 If-Match 更新。缺少安全能力时保留本地内容并拒绝开启同步。应用密码保存在 macOS 钥匙串，不进入数据库、备份或同步文件。
3. 连接后默认自动同步：本地更改先落盘，通常约 5 秒后合批发送，持续编辑时最长约 30 秒安排一轮；启动、回到前台及约每 2 分钟也尝试同步。断网不影响本地保存，重试遵守退避与服务端限流。
4. 白板工具栏的小刷新按钮用于立即同步，右键可打开设置和冲突处理；“数据”菜单也保留入口。暂停同步仍保留待发内容，重新连接原配置后继续。
5. 同一字段的并发不同值保留为候选，可在“处理同步冲突…”选择采用版本；不同字段的更改自动合并。采用版本后清理已解决的旧正文。完成与放弃冲突暂不计入任一结果，待明确处理。
6. 专用云目录完整清空后，新版自动创建新库并重新上传本地项目、事项、完成/放弃记录及尚未解决的候选。原配置已启用时自动开始；尚未启用时点击“连接并合并”。不支持继续读取旧云协议，也不会替用户清理旧云目录。

本地数据库仍由 SwiftData 管理，**不会上传 SQLite 数据库文件或 WAL 文件**。云端布局为：

```text
专用目录/
  library.json                    同步库身份与协议 v3
  index.json                      事项/项目 ID 与最新修订号
  records/
    todo-<UUID>.json               该事项的最新字段、必要业务记录与未解决候选
    project-<UUID>.json            该项目的最新字段与必要代次信息
  _work/                          可恢复工作区，正常空闲无工作文件
    <writerID>.<SHA256>.intent.json   内容不可变的完整恢复输入，确认后删除
    <writerID>.<SHA256>.payload.json  内容不可变的安全创建正文，确认后删除
    <writerID>.probe-{a,b,c}.json   不含业务内容的安全能力探测
```

每个事项/项目一个固定路径，内容更新使用 ETag/If-Match；首次创建延续已验证的条件 PUT 或不覆盖 MOVE。只下载索引中变化的记录，无修改刷新不上传业务内容。每轮最多下载/发布各 24 条记录，之后继续；不用逐条重放历史。单记录上限 8 MiB、索引上限 4 MiB，超限保留完整本地内容并停止相应发送，不截断备注。索引只有 ID/修订号，没有所有备注正文。

本地只保留当前字段/未解决候选、当前有效完成/放弃凭据、待发与在途修改、每条记录的最高确认进度。普通创建/编辑/撤回事件不累计；离线多次改同一字段合并为最后的待发值；在途请求封存后继续编辑，保留下一批最新内容。项目使用当前激活代次及每个写入身份的失效/因果前沿，反复归档恢复不保留整条生命周期链。事项终态、关键时间及必要项目来源属于业务数据，继续保存；无法确认的历史转出时间记为未知。

工作意图和上传正文使用包含内容 SHA-256 的路径，同一路径永不保存另一份不同内容。每次串行处理一项，重试相同字节复用原路径，不将临时文件当历史归档。记录发布前先保存完整意图；任何新版设备均可接续合并、修复索引，确认后删除该不可变路径。后续操作使用不同路径，旧清理不会删到新输入，因此兼容 DELETE 忽略 If-Match 的服务器；业务记录及索引更新仍严格使用条件写入。删除响应丢失可读回确认，没有证明的内容不会因时间过期被删除。正常同步完成后工作文件清空，允许空 `_work/` 目录。断网、权限不足或无法校验的唯一输入会保留并提示，恢复确认后才回收。

自动备份固定为 `Backups/recovery.latest.pindobackup`，先校验、原子替换，再回收应用旧轮换备份和已完成操作的安全副本；不维护每日/每版本历史文件。备份失败保留上一份有效副本，用户手动导出的文件不参与自动回收。本地受管文件使用固定 `.pending` 槽位，成功后消失，中断后重用或恢复。SQLite 的 WAL/SHM 和可复用空页属于数据库维护，不直接删除。

实际连接必须通过条件写入、安全创建及临时文件删除验证；本项目未访问真实坚果云账号联调。同步后的备份恢复使用合并方式，备份缺少的事项不会删除当前内容。已有绑定暂不支持直接更换服务器/账号/目录，但同一专用云目录完整清空后可自动重新初始化。发现已知索引条目丢失、版本回退、记录缺失、身份重复或损坏时停止并保留本地数据。当前采用记录级条件提交，多记录操作可能跨轮到达，依赖未齐时暂存等待；不宣称整个云库一次全局提交。详细协议、边界见规划第 28–30 节。

## 开发与测试

技术栈为 Swift + SwiftUI + Combine + SwiftData，无第三方依赖，无 Python/Conda 运行环境要求。完整 Xcode 用于开发，独立应用日常运行不需要 Xcode。

```sh
zsh scripts/build-app.sh       # Debug
zsh scripts/build-app.sh Release
zsh scripts/test.sh
zsh scripts/package-dmg.sh
```

或用 Xcode 打开 `PinDo.xcodeproj`，选择 `PinDo` / `My Mac` 运行。所有构建产物集中在 `build/`，被 Git 忽略。

- Debug：`local.pindo.development`，数据位于 `~/Library/Application Support/PinDo-Development/`。
- Release：`local.pindo.app`，正式数据位于 `~/Library/Application Support/PinDo/`。
- XCTest：使用任务专属临时目录，结束后清理；不访问正式数据。
- `--demo`：显式内存预览模式，不保存数据。

自动化检查使用真实临时数据库与模拟 WebDAV 服务端，不访问正式数据或真实云端账号。当前 **154 项非 UI 测试通过**，其中同步 88 项、生命周期 10 项。本轮新增 1000 次编辑无流水、100 次项目归档/恢复无父链、其他设备接续上传/补索引、MOVE 与丢失响应恢复、不可变工作清理/拒绝、错误工作文件保护、单份备份与写入失败保护、固定临时槽位和本地升级恢复、独立生成的 v3 编码 fixture。完整记录见规划第 30 节。

图标来自 `asset/pin-do.png`，`scripts/generate-icon.sh` 可生成多分辨率 ICNS。打包脚本先测试、构建 Release，再做本机临时签名和镜像校验；受限环境使用 UDF 镜像，内容为应用、可拖入安装的“应用程序”Finder 替身及安装说明，不包含用户数据库、日志或构建缓存。

SwiftData 物理模型继续使用显式 PersistentModel backing/observation。普通本地库保持逻辑格式 v2，首次启用同步或恢复 v3 备份后使用 v3，包含业务记录、当前字段候选、outbox/inbox 和有限的确认进度；不再永久保存全部编辑正文及传输包。以后修改存储必须验证旧数据迁移，不允许清空原数据库掩盖加载错误。Debug 与 Release 的本地目录和钥匙串服务分离，联调时还应手动指定不同的 WebDAV 测试目录。
